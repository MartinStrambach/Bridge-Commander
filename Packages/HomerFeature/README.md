# HomerFeature

The Homer console section of the main window: sign-in, the process list and the open questions of a Homer instance, natively; everything else as the web console's own page.

Design notes and gotchas for this package. Project-wide conventions are in the root `CLAUDE.md`.

## Notes

- Hybrid by design. The lists (`HomerProcessListView`, `HomerQuestionListView`) are native and poll the API; a process's detail (logs, artifacts, workflow graph, kill/retry) opens the web console's page in a sheet (`HomerWebPageView`, SwiftUI `WebView`/`WebPage`), with "Open in Browser" beside it. The header's Safari button opens the current tab's page the same way
- The API and its JSON are mirrored from the Homer repo: `console/types/homer.ts` (models), `console/lib/api/client.ts` (calls), `app/SERVER.md` (endpoints, auth). Only the fields the lists show are decoded; unknown fields are ignored and unknown statuses decode as `.unknown`, so a newer server keeps working. Timestamps are Unix epoch **seconds**
- **Sign-in works like the web console's cookie mode** (`console/app/(auth)/login/page.tsx`, `lib/auth/auth-context.tsx`): `POST /api/v1/auth/login {username, password}` answers with an `HttpOnly` `homer_session` cookie (12 h by default), which `URLSession` keeps in `HTTPCookieStorage.shared` and sends on every later call — persisted to disk, so a session survives a relaunch like a browser's. No password is stored. `start` (sent once per window from `RootRepositoryView`) probes `GET /api/v1/auth/me`: valid → signed in; 401 → the form. A 401 on any later call is an expired session: back to the form with "Your session expired". Login failures are told apart like the console does: 401 "Invalid credentials", 429 the login limiter (5/min per IP by default — the button stays off for 60 s, since retrying only prolongs the lockout), anything else the error itself
- Every request carries `X-Homer-CSRF: 1`: the backend's CSRF guard rejects cookie-authenticated requests without it (Homer ADR-0016)
- The instance URL (`@Shared(.homerBaseURL)`) is written only by a successful sign-in, so a failed attempt at another instance leaves the working one in place. `HomerEndpoint.normalize` accepts a URL pasted from the browser's address bar: it assumes `https`, drops a trailing console route (`/processes/123`, `/questions`, …) and any query, and keeps a sub-path otherwise. "Change Instance…" in the account menu shows the form over the live session; Cancel returns to it
- Polling follows the console's cadences: processes every 5 s and only while the section is on screen (`appeared`/`disappeared`), open questions every 30 s whenever signed in — the section switcher shows their count as a badge from either section. Each poll is one cancellable loop that fetches immediately; a filter change or "Load more" restarts it, so an answer for the old query never lands after the new one. "Load more" grows `limit` rather than paging, so the refresh keeps every loaded row current
- The web page sheet copies the session cookies (`HomerClient.sessionCookies`) into `WKWebsiteDataStore.default()` before loading, so the page opens signed in. It loads the console as the top-level page: the console sends `X-Frame-Options: DENY` / `frame-ancestors 'none'`, which only an `<iframe>` would trip over. If the cookies are missing the console shows its own login page, which also works
- Question text is Markdown written by an agent. It is rendered inline-only (`AttributedString`, `.inlineOnlyPreservingWhitespace`), and `Text` never loads images — the console renders only an image's alt text for the same reason: an agent-supplied image URL would otherwise beacon on view
- Tests: `.dependencies` (DependenciesTestSupport) gives each test its own app storage for the `@Shared` URL. Build a `State` before passing it to `TestStore`, never inline: `initialState` is an autoclosure evaluated inside the store's own dependencies, so a `@Shared` value written there lands in a different app storage than the one the store's expectations read, and the URL shows up as a spurious `""` → URL diff
