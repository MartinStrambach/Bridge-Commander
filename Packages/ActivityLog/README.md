# ActivityLog

A plain-text log of what the app did — git commands, network requests, errors, uncaught exceptions — that the user can save from Settings ▸ Activity Log and attach to a bug report. No dependencies, so every package can record into it.

## Notes

- **Where entries come from.** `ProcessRunner.runGit` (ProcessExecution, `GitCommandLog`) records git commands; the worktree add/remove helpers in GitCore record themselves, because their git runs inside a `/bin/sh` script. `URLSession.loggedData(for:)` records requests (GitHub/GitLab in GitHosting, YouTrack in ToolsIntegration): method, URL, status, duration, and the first 1000 bytes of the body when the status is not 2xx. `recordingErrors(_:unless:_:)` wraps `PullRequestClient` and `YouTrackClient` so a thrown error (decoding, `unauthenticated`, HTTP failure) is recorded with what was being fetched. The app target installs the uncaught-exception handler and records the launch. Homer's requests are not recorded
- **Read-only git commands are recorded only when they fail** (exit code other than 0 or 1 — 1 is how probes such as `rev-parse --verify --quiet` or `check-ignore` say "no"), unless Settings' "Also record read-only git commands" is on: every refresh runs status/log/diff for every repository. `GitCommandLog.isReadOnly` decides; a subcommand it does not know counts as a change, so it is recorded rather than lost. The toggle is read from user defaults on each command (`includesReadOnlyGitCommandsKey`), keeping this package free of Sharing
- **Missing configuration is not recorded.** A provider without a token (`GitHostingError.missingToken`, `YouTrackServiceError.missingToken`/`.missingBaseURL`) would otherwise add an entry per row per refresh. Cancellation (`CancellationError`, `URLError.cancelled`) is not recorded either: it is how a superseded refresh ends
- **Nothing secret goes in.** Request headers and bodies are never written (they carry tokens); query items named like a token and URL credentials are redacted; the home folder is written as `~`
- **Writes happen on one serial background queue** (`.utility`), so `record` never blocks its caller — the main thread, or a cooperative-pool thread that must not wait on disk. The queue keeps entries in the order they were recorded and writes each entry in one call, so concurrent entries never interleave. Export, size and clear are `async` and go through the same queue, so they see every entry recorded before them. Two paths wait for the queue instead: the uncaught-exception handler (`recordBeforeCrash`, so its entry is on disk before the process dies) and `flush()`, which the app calls on `willTerminateNotification` so a quit does not drop queued entries. The file handle sits in a `Mutex` that only the queue ever takes: uncontended, it is there so the compiler can check `Sendable`. An exception raised on the queue itself may have interrupted a write holding that lock, so the handler then only *tries* it (`withLockIfAvailable`) — losing that one entry beats deadlocking. The file is capped at 2 MB; past it it becomes `activity.previous.log` and a new one starts. `exportData()` joins both under a header (app version, bundle ID, macOS version)
- **Location**: `Application Support/<bundle id>/Logs/activity.log`, so the debug build keeps its own. In a process without a bundle identifier (a package's `swift test`) `shared` writes nothing; GitCore's tests would otherwise leave a log behind on every run. Tests construct their own `ActivityLog(directory:)`
- AppKit catches exceptions raised on the main thread during event handling and only prints them, so those never reach `installUncaughtExceptionHandler`'s handler
