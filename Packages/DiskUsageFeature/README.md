# DiskUsageFeature

The Disk section: a DaisyDisk-style dashboard that scans a volume or folder, shows where the space goes as a sunburst, and removes what is not wanted.

Design notes and gotchas for this package. Project-wide conventions are in the root `CLAUDE.md`.

## Notes

- `DiskUsageReducer` / `DiskUsageView` — the section. `RootRepositoryView` (RepositoryFeature) creates the store with the window and shows the view for `AppSection.disk`, handing it the section switcher as the header's leading view like the Homer console. The view is unmounted while another section is on screen but the store is not, so a scan started here keeps running and the result is there when the section comes back
- `DiskScanner` builds a `DiskNode` tree the way `du` counts (allocated blocks, hard links once across the whole scan, symbolic links not followed, mount points not entered), reading each directory with `getattrlistbulk` as ToolsIntegration's `DerivedDataUsageScanner` does. Unlike that scanner it parses each entry by the attributes reported as returned rather than at fixed offsets (no `FSOPT_PACK_INVAL_ATTRS`), so a file system that cannot report an attribute is told from one reporting zero. The folders still to be read wait in one last-in-first-out `ScanWorkQueue` that `workerCount` (16) threads take from, so every worker stays busy until the end however lopsided the tree; a fan-out fixed at the top two levels left one worker with most of a volume. Threads, not tasks: a worker is blocked in the kernel nearly all the time (sampled: 4% user time), and sixteen blocked tasks would crowd out the cooperative pool. The tree is assembled from the bottom as folders finish in any order: a `FolderInProgress` holds what its folder was read to contain and how many subfolders are still to finish, and becomes a `DiskNode` with the last one. A folder's descriptor stays open until each subfolder has been opened from it with `openat`; with the LIFO queue a worker goes deep before wide, so open descriptors stay around the tree's depth per worker (a GUI app's soft limit is 256). Opening a folder costs the kernel more than reading it, so a folder whose parent reports `ATTR_DIR_ENTRYCOUNT` 0 is a node without being opened: 64% of the 1.7 million folders under `~/Library/Developer` are empty. Measured there on 3.9 million items / 317 GB, warm: 71 s with the fixed fan-out, 32 s with the queue, 17 s skipping empty folders (8 and 32 workers were within 10% of 16); the total matched `du -sk` to the byte (2026-10-16). `DiskScannerBenchmark` repeats the measurement for the folder in `DISK_SCAN_BENCHMARK_ROOT`. A folder keeps nodes for its `filesKeptPerDirectory` (100) largest files and sums the rest into one `DiskNode.Kind.smallerFiles` entry: a whole volume has millions of files, and a node each would cost more memory than the chart could show. A folder that cannot be opened or read is a node with `isInaccessible` set and size 0, and counts toward `DiskScanResult.inaccessibleFolders`; the result's footer then offers the Full Disk Access pane. Progress (`DiskScanProgress`) is sampled from a shared `ScanTally` every 150 ms by a reporter task, not pushed per entry
- `DiskNode` is an immutable class compared by identity. The tree is never copied: the reducer keeps `path`, the chain from the scan root to the folder on screen, and a deletion rebuilds only that chain (`DiskTree.removing(childNamed:from:)`), so the rest of the tree is shared with the previous state. Nodes carry no parent pointer and no full path — only the root's `name` is a path — so a location is told from a chain (`DiskTree.url(of:)`), and a chart segment carries its `ancestry` from the centre's child down
- `SunburstLayout` lays the centre node's descendants out in up to six rings as fractions of a turn, largest first clockwise from the top; children thinner than `minimumSpan` are summed into a trailing grey `rest` segment, and only children at least `minimumSpanToDescend` wide are laid out further. A segment's hue is its midpoint on the circle, so neighbours shade into one another and a folder's children stay in its colour range. `SunburstChartView` draws it in a `Canvas` with hit testing in polar coordinates: clicking a first-ring folder opens it, clicking deeper selects its first-ring ancestor, clicking the centre goes up. Hover is `@State` shared between the chart and the list (`DiskChildrenList`), never a store action: one per mouse move would wake every view bound to the store
- Removal goes through `DiskUsageClient`: Move to Trash (`FileManager.trashItem`, reversible; the space is freed when the Trash is emptied) or Delete Permanently (`removeItem`), both after an alert naming the item and its size, both recorded in the activity log. The summed smaller files and unreadable folders cannot be removed (`DiskNode.isRemovable`). A removed item is subtracted from the tree rather than the scan repeated; Rescan repeats the last scan from its root (`lastScanRoot`, kept when the result is left for the picker)
