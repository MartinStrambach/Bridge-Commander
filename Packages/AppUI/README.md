# AppUI

Shared UI components and diff viewer (+ DiffModelMapping target).

Design notes and gotchas for this package. Project-wide conventions are in the root `CLAUDE.md`.

## Notes

- `ActionButton`, `ToolButton`, `HeaderButton`, `HunkActionButton`
- `DiffViewer`, `DiffLineView`, `HunkCard` (`HunkHeaderView`, `HunkFooterView`, `hunkCardRow()`), `ImageDiffView` — diff display (images render side by side as Before/After; pinch zooms toward the pointer, drag pans when zoomed, double-click resets. Both panes share one `ImageZoom`, whose offset is a fraction of each image's fitted size rather than points, so Before and After stay aligned even when drawn at different sizes). `ZoomableImageLayerView` draws the image as a `CALayer`'s contents with the zoom as the layer's transform, and handles pinch, pan and double-click itself in AppKit (`magnify`/`mouseDown`/`mouseDragged`, with `clickCount == 2` for the reset). Not as SwiftUI gestures: a `.onTapGesture(count: 2)` beside a `DragGesture` made AppKit hold the drag's events back waiting for a second click and deliver them in bursts of ~25 every ~0.6 s (measured 2026-09-29), so panning jumped while pinching stayed smooth
- `DiffViewer` renders diff lines with a `List`, not a `ScrollView` + `LazyVStack`. A lazy stack reports its content's height as its own ideal height, so a large diff handed the enclosing sheet an ideal size of ~10⁶ pt that changed every time more rows were measured; the sheet re-measured, the stack re-estimated, and the main thread spun in `LazyLayoutViewCache.updateItemPhases` / `LazyStack.measureEstimates` for minutes (hang reports 2026-09-06 and 2026-09-07 — flattening the stack in v0.6.7 did not help, the signature was identical). `List` is `NSTableView`-backed: rows recycle and its ideal size is 0×0 regardless of row count
- Hunk header, lines and footer are emitted as sibling rows of one `List`, deliberately not as a `Section` — a plain-style `List` pins section headers, which would make hunk headers sticky. Rows need `.listRowInsets(EdgeInsets())` and `.listRowSeparator(.hidden)` (see `diffListRow()`), plus `defaultMinListRowHeight` of 1 so content height wins and no gap opens in the card's side borders. Do not add `.listRowBackground` — it costs ~40% of scroll time and changes nothing visually
- `DiffViewer` has two inits: the staging one takes the hunk stage/unstage/discard closures, `init(diff:)` is read-only and renders hunk headers without action buttons. `FileChangeRow` likewise has `init(file:)` for a row with no staging checkbox
- `GitOperationProgressView`, `BannerView`, `EmptyStateView`, `ScrollableAlertReducer` / `ScrollableAlertView` (in `ScrollableErrorAlertView.swift`)
- `View.windowTitleBarArea()` — the main window is `.hiddenTitleBar`, so the app's own top bars (list header, terminal toolbar, terminal sidebar header) stand in for the title bar: a double-click there zooms/minimizes per the system's title bar setting (`AppleActionOnDoubleClick`), a drag moves the window. SwiftUI gestures (`onTapGesture(count: 2)` + `WindowDragGesture`), not an `NSView` overriding `mouseDown`: the hosting view routes clicks itself and reached a background `NSView` only over part of the bar. Apply it *before* any `.background(Color…)`, or the color sits in front and takes the clicks
- `UIFontScale` — the app's text scaling. macOS ignores `dynamicTypeSize` (a text style renders at one size whatever it is set to — checked 2026-10-06), so views write **`.scaledFont(.caption)`** / `.scaledFont(.body, design: .monospaced)` / `.scaledFont(size: 12)` instead of `.font(...)`; the modifier multiplies the style's macOS point size by the `uiFontScale` environment value. At scale 1 it returns the text style itself, so the default renders exactly as before. `View.uiFontScale(_:)` sets the scale plus a scaled body font for text with none of its own (no font at all at scale 1); it is one modifier chain rather than an `if`, because a branch at the root would reset every window's state whenever the setting crossed 1. Keep `.font(.system(size:))` only where the glyph sits in a fixed-size frame (the merge badge in `RepositoryIcon`, `HeaderButton`, avatar initials). `GitGraphRowView.rowHeight(scale:)` grows with it
- Controls AppKit draws ignore an inherited font (measured 2026-10-06 with `NSHostingView.fittingSize`), so the root font does not reach them: push and bordered buttons only take a font set *inside* their label, at every control size — use **`.buttonStyle(.scaledBordered)` / `.scaledBorderedProminent` / `.scaledAutomatic`** (`ScaledButtonStyle`) instead of `.bordered` / `.borderedProminent` / no style on a text button; it puts the control size's title size × scale in the label, and passes the native button through untouched at scale 1. A `.borderlessButton` menu's label is flattened by AppKit, which drops `scaledFont`'s environment read and keeps only a literal font, so those views read `@Environment(\.uiFontScale)` and write `.font(.system(size: 12 * uiFontScale))` on the label `Text` (`GitActionsMenuView`, `TuistButtonView`, `YouTrackButtonView`). Plain/borderless buttons, toggles, steppers and text fields follow the inherited font as-is; a menu-style `Picker`'s popup title and segmented pickers stay at the system size whatever is set
- `FileChangeRow`, `SectionHeader`, `RepositoryIcon`
- `AppSection` / `AppSectionSwitcher` — the main window's top-level sections (Repositories, Homer) and the segmented-looking switch at the start of every section's header, with an optional count badge per section. Plain buttons rather than a segmented `Picker`: a segmented picker ignores the app's text scale and cannot carry a badge. Here rather than in a feature package because both RepositoryFeature and HomerFeature draw it
- The **`DiffModelMapping`** target (same package, separate product) holds the `GitCore.*.toAppUI()` conversions. It is where AppUI and GitCore meet, so the `AppUI` target itself stays free of any git dependency and the mapping is not duplicated per feature. Import it alongside `AppUI` wherever a GitCore diff is rendered
