# AppUI

Shared UI components and diff viewer (+ DiffModelMapping target).

Design notes and gotchas for this package. Project-wide conventions are in the root `CLAUDE.md`.

## Notes

- `ActionButton`, `ToolButton`, `HeaderButton`, `HunkActionButton`. `HeaderButton` is borderless (a round highlight on hover), because the list header groups runs of them into Liquid Glass capsules (`glassEffect`); a bordered bezel inside the glass would double the chrome
- `DiffViewer`, `DiffLineView`, `HunkCard` (`HunkHeaderView`, `HunkFooterView`, `hunkCardRow()`), `ImageDiffView` — diff display (images render side by side as Before/After; pinch zooms toward the pointer, drag pans when zoomed, double-click resets. Both panes share one `ImageZoom`, whose offset is a fraction of each image's fitted size rather than points, so Before and After stay aligned even when drawn at different sizes). `ZoomableImageLayerView` draws the image as a `CALayer`'s contents with the zoom as the layer's transform, and handles pinch, pan and double-click itself in AppKit (`magnify`/`mouseDown`/`mouseDragged`, with `clickCount == 2` for the reset). Not as SwiftUI gestures: a `.onTapGesture(count: 2)` beside a `DragGesture` made AppKit hold the drag's events back waiting for a second click and deliver them in bursts of ~25 every ~0.6 s (measured 2026-09-29), so panning jumped while pinching stayed smooth
- `DiffViewer` renders diff lines with a `List`, not a `ScrollView` + `LazyVStack`. A lazy stack reports its content's height as its own ideal height, so a large diff handed the enclosing sheet an ideal size of ~10⁶ pt that changed every time more rows were measured; the sheet re-measured, the stack re-estimated, and the main thread spun in `LazyLayoutViewCache.updateItemPhases` / `LazyStack.measureEstimates` for minutes (hang reports 2026-09-06 and 2026-09-07 — flattening the stack in v0.6.7 did not help, the signature was identical). `List` is `NSTableView`-backed: rows recycle and its ideal size is 0×0 regardless of row count
- Hunk header, lines and footer are emitted as sibling rows of one `List`, deliberately not as a `Section` — a plain-style `List` pins section headers, which would make hunk headers sticky. Rows need `.listRowInsets(EdgeInsets())` and `.listRowSeparator(.hidden)` (see `diffListRow()`), plus `defaultMinListRowHeight` of 1 so content height wins and no gap opens in the card's side borders. Do not add `.listRowBackground` — it costs ~40% of scroll time and changes nothing visually
- `DiffViewer` has two inits: the staging one takes the hunk stage/unstage/discard closures, `init(diff:)` is read-only and renders hunk headers without action buttons. `FileChangeRow` likewise has `init(file:)` for a row with no staging checkbox
- `PopUpMenuButton` — a button (by default a menu's title and a chevron, `PopUpMenuTitle`; the row's "⋯" menu passes an icon) that builds an `NSMenu` from its `PopUpMenuEntry` list only when pressed and drops it from the button's bottom edge. The repository rows' menus (Git Actions, Tuist, YouTrack, "⋯") use it instead of a SwiftUI `Menu`: a `Menu` is an NSPopUpButton built with the row, empty or full, and the list rebuilds rows as they scroll into view (RepositoryFeature's README has the measurements). Entries are written in a `@PopUpMenuBuilder` block of `PopUpMenuAction`s plus `PopUpMenuEntry.section` / `.submenu` / `.share` / `.divider` (write `PopUpMenuAction(…)` rather than a leading-dot `.action(…)`: a line starting with `.` continues the expression above it). `.share` is AppKit's own Share submenu (`NSSharingServicePicker.standardShareMenuItem`, its picker kept alive as the item's `representedObject`). A destructive item gets a red title; an item's `help` is its tooltip. An item's icon is set with `preferredImageVisibility = .visible`: macOS 27 hides menu item images by default (the counterpart of `.labelStyle(.titleAndIcon)` on a SwiftUI `Menu`). Built with `autoenablesItems` off, so an item's `isEnabled` is what shows. Its label is SwiftUI's, so unlike a pull-down's AppKit-drawn one it inherits its surroundings: `PopUpMenuTitle` pins the primary colour and the "⋯" icon its size, or the repository group's row, a `List` section header, draws them secondary and smaller
- `View.appKitPresentation(isPresented:present:)` — shows something AppKit draws relative to a view (`PopUpMenuButton`'s menu, the row's share picker) while `isPresented` is true. An anchor `NSView` sits behind the view only meanwhile, so the view costs nothing extra until used; `present` runs from a `Task` after the SwiftUI update that added the anchor, because `NSMenu.popUp` runs a tracking loop and must not run inside one. The row's Share button cannot simply be a `PopUpMenuButton` showing the Share submenu: `standardShareMenuItem`'s submenu is `nil` until AppKit displays it (checked 2026-10-11), so it shows `NSSharingServicePicker` itself
- `GitOperationProgressView`, `BannerView`, `EmptyStateView`, `ScrollableAlertReducer` / `ScrollableAlertView` (in `ScrollableErrorAlertView.swift`)
- `View.windowTitleBarArea()` — the main window is `.hiddenTitleBar`, so the app's own top bars (list header, terminal toolbar, terminal sidebar header) stand in for the title bar: a double-click there zooms/minimizes per the system's title bar setting (`AppleActionOnDoubleClick`), a drag moves the window. SwiftUI gestures (`onTapGesture(count: 2)` + `WindowDragGesture`), not an `NSView` overriding `mouseDown`: the hosting view routes clicks itself and reached a background `NSView` only over part of the bar. Apply it *before* any `.background(Color…)`, or the color sits in front and takes the clicks
- `UIFontScale` — the app's text scaling. macOS ignores `dynamicTypeSize` (a text style renders at one size whatever it is set to — checked 2026-10-06), so views write **`.scaledFont(.caption)`** / `.scaledFont(.body, design: .monospaced)` / `.scaledFont(size: 12)` instead of `.font(...)`; the modifier multiplies the style's macOS point size by the `uiFontScale` environment value. At scale 1 it returns the text style itself, so the default renders exactly as before. `View.uiFontScale(_:)` sets the scale plus a scaled body font for text with none of its own (no font at all at scale 1); it is one modifier chain rather than an `if`, because a branch at the root would reset every window's state whenever the setting crossed 1. Keep `.font(.system(size:))` only where the glyph sits in a fixed-size frame (the merge badge in `RepositoryIcon`, `HeaderButton`, avatar initials). `GitGraphRowView.rowHeight(scale:)` grows with it
- Controls AppKit draws ignore an inherited font (measured 2026-10-06 with `NSHostingView.fittingSize`), so the root font does not reach them: push and bordered buttons only take a font set *inside* their label, at every control size — use **`.buttonStyle(.scaledBordered)` / `.scaledBorderedProminent` / `.scaledAutomatic`** (`ScaledButtonStyle`) instead of `.bordered` / `.borderedProminent` / no style on a text button; it puts the control size's title size × scale in the label, and passes the native button through untouched at scale 1. A `.borderlessButton` menu's label is flattened by AppKit, which drops `scaledFont`'s environment read and keeps only a literal font: such a menu has to read `@Environment(\.uiFontScale)` and write `.font(.system(size: 12 * uiFontScale))` on the label `Text` (the row's menus did, before they became `PopUpMenuButton`s, whose label is SwiftUI's own and scales normally). Plain/borderless buttons, toggles, steppers and text fields follow the inherited font as-is; a menu-style `Picker`'s popup title and segmented pickers stay at the system size whatever is set
- `FileChangeRow`, `SectionHeader`, `RepositoryIcon`
- `AppSection` / `AppSectionSwitcher` — the main window's top-level sections (Repositories, Homer) and the segmented-looking switch at the start of every section's header, with an optional count badge per section. Plain buttons rather than a segmented `Picker`: a segmented picker ignores the app's text scale and cannot carry a badge. Here rather than in a feature package because the Homer console's header shows it too: `RootRepositoryView` passes it to `HomerConsoleView` as the header's leading view. The Homer segment's icon is the Homer console app's icon (`Resources/HomerIcon.tiff`, cropped from `App/HomerConsole/Assets.xcassets/AppIcon.appiconset/icon_512x512.png` in that repository to its opaque rounded square, without the margin and drop shadow) — copy it again if the app icon changes, as a 32 px and a 64 px PNG merged with `tiffutil -cathidpicheck HomerIcon.png HomerIcon@2x.png -out HomerIcon.tiff`. The multi-resolution TIFF is read once with `NSImage(contentsOf:)`, which picks the 64 px bitmap on Retina. Not `Bundle.module.image(forResource:)` with loose `@2x` PNGs: it looks in the bundle's asset catalog first, and CoreUI logs "unable to find a bundle … with identifier 'appui.AppUI.resources'" for a resource bundle that has none. A bitmap is not sized by the font like a symbol, so it is framed to the headline's point size (+3) times `uiFontScale`
- The **`DiffModelMapping`** target (same package, separate product) holds the `GitCore.*.toAppUI()` conversions. It is where AppUI and GitCore meet, so the `AppUI` target itself stays free of any git dependency and the mapping is not duplicated per feature. Import it alongside `AppUI` wherever a GitCore diff is rendered
